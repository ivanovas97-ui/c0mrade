# Интеграция Proxmox VE с Zabbix

## Требования

- Доступ к консоли Proxmox VE с правами `root` (или возможность выполнять команды `pveum`).
- Установленный и настроенный Zabbix Server (веб-интерфейс).
- Шаблоны в Zabbix:
  - `Linux by Zabbix agent`
  - `Proxmox VE by HTTP`
- Сетевой доступ из Zabbix Server к Proxmox VE по HTTPS (порт 8006 по умолчанию) и по агенту (порт 10050).

## Часть 1. Настройка Proxmox VE

Все команды выполняются на узле Proxmox VE (в shell/SSH).

### 1.1. Создание роли

Создаём отдельную роль с минимально необходимым набором прав:

```bash
pveum role add ZabbixMonitoring --privs "Datastore.Audit Sys.Audit VM.Audit"
```

- `ZabbixMonitoring` — имя роли.

### 1.2. Создание группы и назначение прав

```bash
pveum group add zabbix
pveum acl modify / -group zabbix -role ZabbixMonitoring
```

- `zabbix` — имя группы;
- права роли назначаются на корень `/` (все объекты).

### 1.3. Создание пользователя

```bash
pveum user add zabbix@pam
pveum user modify zabbix@pam -group zabbix
```

- `zabbix@pam` — системный пользователь Proxmox;
- добавляется в группу `zabbix`.

### 1.4. Получение API-токена

```bash
pveum user token add zabbix@pam monitoring -privsep 0
```

- `zabbix@pam` — пользователь, для которого выпускается токен;
- `monitoring` — идентификатор токена;
- `-privsep 0` — токен наследует права пользователя (без отдельного набора привилегий).

> ⚠️ **Важно:** скопируйте и сохраните значение поля `value` — это секретный ключ токена. Повторно узнать его не получится.

Итоговый идентификатор токена для Zabbix: `zabbix@pam!monitoring`.

На этом настройка на стороне гипервизора завершена.

## Часть 2. Добавление узла в Zabbix

### 2.1. Создание узла сети

1. Откройте веб-интерфейс Zabbix.
2. Перейдите в **Мониторинг → Узлы сети**.
3. Нажмите **Создать узел сети** (справа вверху) и заполните поля:
   - **Имя узла сети** — для активных проверок должно совпадать с `Hostname` в агенте, иначе активные проверки работать не будут.
   - **Шаблоны** — выберите:
     - `Linux by Zabbix agent`
     - `Proxmox VE by HTTP`
   - **Группы узлов сети** — выберите существующую или укажите новую (достаточно ввести желаемое название).
   - **Интерфейсы** — добавьте интерфейс с типом **Агент** и укажите адрес узла или его доменное имя.

### 2.2. Макросы узла сети

Перейдите в раздел **Макросы → Макросы узла сети и унаследованные** и заполните **только следующие макросы**:

| Макрос | Значение |
|---|---|
| `{$PVE.TOKEN.ID}` | Идентификатор токена, например `zabbix@pam!monitoring` |
| `{$PVE.TOKEN.SECRET}` | Секретный ключ токена, сохранённый на шаге [1.4](#14-получение-api-токена) |
| `{$PVE.URL.HOST}` | IP-адрес или доменное имя гипервизора |

> ⚠️ **Указывайте только эти три макроса.** Не добавляйте другие макросы `{$PVE.*}` — достаточно `{$PVE.TOKEN.ID}`, `{$PVE.TOKEN.SECRET}` и `{$PVE.URL.HOST}`.

Сохраните узел.

## Проверка

Через некоторое время Zabbix начнёт собирать данные:

- по самому хосту виртуализации;
- по работающим на нём виртуальным машинам и контейнерам.

Также начнут срабатывать триггеры — например, Zabbix уведомит о том, что некоторые ВМ и контейнеры на узле не запущены.

---

## Примечания

- Секрет токена (`value`) отображается **единожды** при создании — храните его в защищённом месте.
- Для активных проверок имя узла в Zabbix должно совпадать с `Hostname` в Zabbix-агенте на хосте Proxmox.
- Минимально необходимые права роли: `Datastore.Audit`, `Sys.Audit`, `VM.Audit`.
- Если планируется мониторинг только через HTTP (без агента), шаблон `Linux by Zabbix agent` и интерфейс типа «Агент» можно не добавлять — но тогда не будут собираться метрики ОС хоста.
